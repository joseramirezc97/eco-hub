This document outlines the mandatory architectural patterns and principles for all cloud-native applications within the Ecosystem Hub. These standards ensure high availability, scalability, and seamless integration across the global infrastructure.

Core Principles

Our architecture follows the "Five Pillars of Resilience": Scalability, Security, Efficiency, Reliability, and Observability. Every component must adhere to the asynchronous-first communication pattern to prevent cascading failures.

Fig 1.1: Standard High-Level Interaction Model

Implementation Pattern

When implementing the service mesh, developers must ensure that sidecar proxies are configured for mutual TLS (mTLS). Below is a reference configuration for the environment manifest:

apiVersion: networking.ecosystem.io/v1alpha3
kind: ServiceEntry
metadata:
  name: external-svc-passthrough
spec:
  hosts:
  - api.external-partner.com
  ports:
  - number: 443
    name: https
    protocol: TLS
  resolution: DNS
  location: MESH_EXTERNAL

Performance Requirements

  • check_circle P99 Latency must remain below 150ms for global traffic.
  • check_circle Auto-scaling must trigger when CPU usage exceeds 70% for >2 mins.
  • check_circle All egress traffic must pass through the verified hub egress proxy.
